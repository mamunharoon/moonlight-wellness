# WakeWise — Release Readiness Register

**Purpose:** one evidence-based record of what is actually complete, partial, or missing for internal TestFlight, external TestFlight, and public App Store release — so completed work is not redone and unfinished work is not claimed as done.

**Methodology:** every row below is sourced from a file in this repository at the commit stated below, or an existing documented verification report in `docs/`. Nothing about the live Supabase project, Stripe dashboard, Apple Developer/App Store Connect account, Vercel project, or Codemagic account is asserted unless a repo file documents a specific, dated verification of it — those are explicitly labelled **"requires dashboard verification."** Status values used throughout:

- **VERIFIED COMPLETE** — implemented, and either verifiable from code/tests alone or confirmed by a dated in-repo verification record.
- **IMPLEMENTED — DEVICE/DASHBOARD VERIFICATION REQUIRED** — code exists and looks correct, but the only way to actually confirm it works is a physical iPhone, Xcode/macOS, or an external dashboard.
- **PARTIAL** — some real part is built; a specific, named piece is missing.
- **PLANNED ONLY** — a design/spec document exists; no working code.
- **NOT FOUND** — no evidence of this in the repository.
- **NOT APPLICABLE** — the requirement doesn't apply given how this is actually built (reason given).
